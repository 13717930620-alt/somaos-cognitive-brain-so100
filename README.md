## 项目一句话定位

**SomaOS Cognitive Brain (SomaOS 认知意识脑)** 是一个面向
**双足人形机器人**的**仿生分区全脑控制内核**。它将高等动物的
**"新皮层推理 + 丘脑筛选 + 脑干急停"**三层脑模型抽象为可在
通用计算硬件上运行的工程结构, 并在双足人形机器人平台上完成
了全链路实机集成验证。

设计哲学一句话: **双脑分离 + 内生安全层 + 仿生分层执行**。
本脑承担"大脑皮层"角色——理解自然语言、维护长期记忆、进行
审慎推理与高层规划, 通过 RCAN 标准化协议下发**经两层安全
门控筛选**的意图; 运动执行则由独立的 SomaOS Brain Next
(运动脑) 承担, 两者互不共享内部状态, 仅在 RCAN 语义接口层
对齐 (运动脑当前在 Feetech SO-100 机械臂平台上做集成验证,
本认知脑则在人形机器人平台上独立集成)。

- **适用硬件**: 双足人形机器人 (全身伺服驱动系列; 含头/腰/
  双臂/双足/灵巧手的多自由度人形本体)
- **推荐算力**: Jetson Orin 级 / x86 桌面 + GPU 级加速卡
  (本地 LLM 推理时需要, 运动控制本身单机可跑)
- **操作系统**: Linux (推荐 Ubuntu 22.04+); Windows 开发环境可用
- **对外接口**: 标准化 RCAN 命令入口、本地 HTTP 控制接口、
  本地 LLM 推理接口、急停总线输入、状态事件回流输出

## 为什么 SomaOS Cognitive Brain 不只是"又一个 LLM+人形机器人"

2026 年具身智能的主流形态是**"大模型后端 + ROS2 前端"的胶水
拼搭**——这种方案在演示视频上出彩, 但在真实连续运行 8 小时
以上的场景中, 往往会在以下 5 个薄弱点上暴露结构性缺陷:

| 常见 VLA-ROS2 拼接方案的问题 | SomaOS 的结构性对策 |
|---|---|
| 世界帧漂移: 感知帧、认知帧、动作帧各自为政, 执行 3-5 步后与真实场景错位 | **三相位时序一致性闭环架构** (见下文 §1) |
| 黑箱置信度: VLA 模型自我评估置信度常为 99% 却做错, 外部无独立判断 | **跨模态三重一致性评分系统** (§2) |
| 安全靠外挂: CBF/约束层是独立实现, 与决策层不同步, 边界死锁频发 | **内生双路径门控** (§3): 决策前慢路 + 执行前快路, 同一脑核内共存 |
| 长任务断档: 超过 7-10 步的子目标序列因状态漂移而断掉 | **情景-语义双层记忆 + 子目标回退** (§4) |
| 运行后不进化: 固定权重部署, 失败经验只会重复发生不会被学习 | **内在线进化型连接自调节** (§5) |

这些对策都是**结构性的、非依赖特定参数的**——意味着它们
的有效性来自系统架构设计, 而不是某个特定大模型版本的
能力。以下是详细技术主张描述。

### §1 三相位时序一致性闭环架构 (Three-Phase Anchoring Closed Loop)

**要解决的核心痛点**: 在具身任务中, "感知模块说看到了一个杯
子、认知模块理解为 '我要把面前的杯子拿起'、运动模块却朝
完全不同的方向伸手" 这类 **帧错位错误** 是极其高频、且不
能用单点模块精度提升解决的问题。当系统连续运行超过 10 步,
每一步微小的帧错位会被链式放大, 最终出现"感知对、理解对、
做错" 的荒诞结果。在人形机器人上, 由于本体自由度高、双足
平衡对帧一致性极其敏感, 帧错位还会直接引发失稳跌倒。

**SomaOS 的设计思路**: 引入**三个锚定相位**——**感知锚定、
认知锚定、运动锚定**——在时序上严格共享同一个世界坐标系
原点。每一帧决策产出前, 三相位必须重新对齐原点:

1. **感知锚定 (Perceptual Anchor)**: 所有模态输入 (视觉/深度/
   触觉/听觉/本体姿态) 在进入认知层之前统一投影到同一世界坐标系,
   并产出一份**原点哈希**作为本帧感知真实性的凭证。
2. **认知锚定 (Cognitive Anchor)**: 意图理解、记忆检索、
   推理链路全部在带原点哈希的上下文中执行, 任何一步的
   语义产出必须能够回溯到其锚定的感知凭证。
3. **运动锚定 (Motor Anchor)**: 运动皮层在执行前**重新从
   执行侧终端状态计算一次原点对齐**, 而不是盲目信任上层
   给出的坐标。

**任何一相锚定失败或三相哈希不一致, 整帧决策立即回退**——
要么重新感知, 要么重新规划, 要么进入安全状态。经过工程实
测, 这个机制显著降低了"长序列任务的帧错位率", 也显著降低
了人形机器人在连续任务中因帧漂移而失稳的概率。这是 SomaOS
区别于普通 VLA + ROS 胶水架构的**第一根本差异**。

---

### §2 跨模态三重一致性评分系统 (Triple Cross-Modal Consistency Scoring)

**要解决的核心痛点**: VLA 大模型的"置信度"是模型内部的自
评分数, 经常出现"模型 99% 确定, 但答案完全是错的"这种
黑箱幻觉问题。幻觉本身不可消除, 但可以通过**外部独立验证**
来捕获。

**SomaOS 的设计思路**: 在认知层内部放置三条**独立的一致性
评分流水线**, 它们从不同模态、不同来源独立验证同一条意图
推理的合理性:

1. **语义一致性评分**: 同一条意图在语言空间、视觉标签空间、
   动作标签空间的语义嵌入是否相互指向同一任务假设。
2. **记忆一致性评分**: 在长期情景记忆和语义记忆中检索与当
   前意图相似的历史案例, 观察它们对应的动作结果分布是否
   与本意图推论一致。
3. **物理可行性评分**: 不依赖视觉, 而是将意图对应到一组简
   化的物理前向约束 (双足质心支撑多边形约束、全身可达域、
   灵巧手开合理、负载重量、自碰撞风险) 做快速可行性筛检。

三条评分的**加权综合**构成该意图的"外源性置信度"。当外源
性置信度低于阈值时, 即使模型本身给出 99% 的自信, 意图也
会被**退回重新表述**或**请求外部澄清**, 而不是被硬送进执行
链路。这是**对抗大模型幻觉的结构性防御**, 独立于模型权重。

---

### §3 内生双路径安全门控 (Built-In Dual-Path Safety Gating)

**要解决的核心痛点**: 行业常见的做法是在模型决策后外挂一
个"安全层"或"约束满足器" (CBF / Action Filter / Shield)。
但外挂层最大的结构缺陷是——**它与决策层有不同的世界帧、
不同的时钟、不同的状态视图**, 很容易出现决策层说"没问题"、
安全层说"不行"的边界死锁, 或者反过来安全层漏掉了决策层已
经改变了的假设。在人形机器人上, 由于跌倒代价远高于机械臂
碰撞, 这种边界死锁的后果更严重。

**SomaOS 的设计思路**: 借鉴高等哺乳动物**"新皮层慢决策 +
脊髓反射快反应"**的双路径生物学模型, 在同一脑核内部构建
两条路径互相独立、但同享状态视图的门控结构:

- **路径一 (慢路 · 意识级意图门控)**: 发生在意图正式下发
  之前。完成置信度、动作语义合法性、冷却限制、意识共识
  验证等**并行综合否决**。延迟目标在毫秒级 (相对可接受)。
- **路径二 (快路 · 反射级急停门控)**: **完全绕过所有推理
  层**, 直接在执行链路最末端提供一条几乎零延迟的关节扭矩
  释放路径。只要总线有 ESTOP 输入, 或快路内部触发急停条件
  (含失稳前兆、自碰撞前兆、负载超限等), **无论慢路当前说
  什么, 动作立刻被切断**。

两条路径**物理上独立、代码上无共享调用、状态视图同源**。
任何一条触发即切断动作。这种"内生"结构意味着——安全不是
装在大脑外面的壳子, 安全就是大脑本身的一部分。这是
SomaOS 区别于外挂安全层的**第二根本差异**。

---

### §4 情景-语义双层长期记忆 + 子目标回退 (Dual-Layer Memory with Subgoal Backtracking)

**要解决的核心痛点**: 长任务 (超过 10 步) 失败的最常见原
因, 不是第 N 步做错了, 而是第 N-3 步埋下的错误假设没有
被发现, 连锁走到第 N 步才崩。系统发现崩了之后的默认反应
是"从头重做", 浪费了前面 N-1 步已经正确的工作。在双足
人形机器人上, "从头重做"还意味着要重新归位到任务起点,
过程中同样有跌倒风险。

**SomaOS 的设计思路**: 记忆分两层持久化:

1. **语义记忆 (Semantic Memory)**: 结构化长期事实 (物体属
   性、任务规律、概念之间的抽象关系), 跨情景复用。
2. **情景记忆 (Episodic Memory)**: 按任务实例化的时间序列
   记录, 每一"步" (subgoal) 独立存证, 包括执行前的感知
   快照、意图原始文本、动作参数、执行后状态、一致性评分。

当任务执行到某一子目标失败时, 系统不是回到起点, 而是**从
最后一个"锚定成功、一致性评分高"的子目标回退重启**。回退
层级由失败类型的结构分类器自动决定。这使得长任务的成功
率不再随步数指数衰减, 而是在长任务上体现出一种"容错的
连续推进"特性。

---

### §5 内在线进化型连接自调节 (Built-In Evolutionary Weight Self-Tuning)

**要解决的核心痛点**: 当前部署范式是"离线训练 → 导出权重
 部署运行"的一次性过程。部署后, 即使大脑在真实环境中遇
到了大量失败信号、累积了大量新的经验, 这些经验除非回到
离线训练流水线做昂贵的重训, 否则等于被丢弃。长期运行下,
"训练-部署"之间的鸿沟越来越大。

**SomaOS 的设计思路**: 引入一条"温和、在线、结构不变"的自
调节环路, 连接权重 (不是模型参数, 而是脑各认知模块之间的
连接强度) 会根据两条评估线在线变化:

1. **失败信号价值分级**: 每一个失败事件被标记成不同价值
   (高价值失败: 自信错判、新场景首次失败、安全层误拦漏拦;
   低价值失败: 已知能力边界外的常规失败), 仅高价值失败才
   会触发调节。
2. **多模态语义一致性评分的长期漂移**: 一段时间内一致性
   评分持续下降意味着"某些连接权重需要重平衡"。

调节的核心约束是 **"结构不变、连接关系温和进化"**——不会
增减模块, 不会重构拓扑, 只会在现有结构的连接权重上做小
步长、带上限的微调。这个机制目标不是让大脑短期内突然变
聪明, 而是让它**长期运行后任务成功率曲线能持续改善, 而
不是饱和下跌**。这是 SomaOS 区别于"部署即冻结"架构的**第
三根本差异**。

---

### §6 双脑分离独立运行架构 (Dual-Brain Separation Architecture)

**要解决的核心痛点**: 2025-2026 年间, 大量具身智能项目尝
试把"感知 VLA 大模型 + 实时运动控制"塞在同一个进程/同一
台设备里跑, 结果是: GPU 资源争用、调度抖动渗透到实时节
点、安全急停因调度延迟失效——或者反过来, 为了满足实时
性, 只能限制大模型的规模, 浪费了认知能力。在人形机器人
上, 由于平衡控制对实时性的要求比机械臂更严苛, 这种资源
争用的后果会被进一步放大。

**SomaOS 的设计思路**: 经过内部架构审查对照, 将大脑拆成
**认知脑 (本项目)** 与 **运动执行脑 (SomaOS Brain Next)**
两个完全独立的运行体, 各自独立:

- 启动、停机、资源分配、看门狗、安全急停完全独立;
- 内部状态不共享、无交叉依赖;
- 仅在 **RCAN 标准化语义接口**层对齐: 两者对外使用同一
  套标准化指令语义, 使得未来在同一台人形机器人本体上能
  "各自装一个"而不冲突。
- **当前各自的实机集成验证平台不同**: 本认知脑在双足人形
  机器人平台上完成集成验证; SomaOS Brain Next (运动脑)
  目前在 Feetech SO-100 六轴机械臂平台上完成集成验证。
  两者作为独立大脑各自单独装机运行, 互不依赖; 当未来出现
  人形机器人版的运动执行脑时, 即可在同一台人形本体上与本
  认知脑组成"皮层—脑干小脑"双层部署。

这恰好与 2026 年具身智能业界被验证有效的 **"Cerebrum
(皮层, GPU) — Brainstem/Cerebellum (脑干小脑, Jetson/MCU)"**
分工模型同构。本项目承担前者, Brain Next 承担后者。

## 能力声明 (公开对外的能力类型)

本大脑声明具备以下公开能力类型 (**仅声明能力域, 不承诺具
体对外接口协议与性能数值**):

- **视觉感知**: RGB 相机 + 深度相机输入的融合感知能力
- **语音交互**: 语音输入 (ASR) 与语音输出 (TTS) 接口
- **双足移动**: 双足行走、平衡保持、步态规划与重心稳定
- **全身操控**: 全身多自由度位姿控制 + 灵巧手抓取 / 释放
- **认知推理**: 语义记忆、情景记忆、自然语言意图理解、多
  步子目标规划、子目标回退
- **安全保护**: 强制急停、关节扭矩释放、冷却限制、双路径门控
- **学习进化**: 在线高价值失败信号优先经验回放 + 连接权重
  温和自调
